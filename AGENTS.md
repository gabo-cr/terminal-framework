# Instrucciones para Codex

- Lee `docs/project.md` antes de trabajar. Describe la arquitectura, el comportamiento actual y los límites del producto. Consulta `docs/core.md` para las interfaces del motor y las guías de contratos para los JSON.
- Usa pnpm con la versión fijada en `package.json`. Conserva `pnpm-lock.yaml` como único lockfile. No añadas herramientas, dependencias ni scripts sin necesidad real.
- Trabaja con cambios pequeños y verificables, limitados al alcance solicitado. Conserva cambios existentes del usuario; no cambies la versión, hagas commits, crees tags o publiques sin autorización.
- Mantén Core independiente de React, DOM, HTTP y almacenamiento. Reutiliza CommandRegistry, ContentCatalog, esquemas Zod, tipos derivados y reglas de nombres y rutas; no dupliques configuración ni validaciones.
- Respeta los contratos públicos de `docs/configuration.md`, `docs/commands.md` y `docs/content.md`. Cualquier JSON, referencia o ruta inválida impide ready. Los Markdown se descargan bajo demanda, fuera del arranque estricto.
- Mantén `loadApplication → bootstrapApplication → createCommandRuntime`, con una composición por intento y sesión incluso en StrictMode. Reintentar o cambiar el cargador crea una sesión nueva y descarta resultados obsoletos.
- Usa `VITE_CONTENT_BASE_URL` para configuración y contenidos externos. No acoples el framework a un sitio personal. La caché es en memoria por proveedor y sesión.
- useTerminal posee los historiales y el bloqueo de ejecuciones. clear conserva bienvenida, historial de comandos y caché. TerminalPrompt gestiona la lista de completado; no replica el parser ni las coincidencias. Tab completa al final, Enter ejecuta el texto literal y las flechas sin modificadores seleccionan solo con lista abierta; el foco permite salir del campo.
- Las sugerencias del Core consultan solo metadatos; no ejecutan comandos ni descargan Markdown. COMMAND_NOT_FOUND conserva código y mensaje, con alternativas opcionales. Mantén es/en y el patrón combobox/listbox accesible.
- Los componentes no acceden a fetch. MarkdownRenderer usa react-markdown sin HTML crudo ni plugins adicionales; no ejecuta comandos. Conserva el scroll local y evita anunciar documentos completos.
- Mantén pruebas en `tests/`, fixtures en `tests/fixtures/` y utilidades en `tests/support/`. No publiques fixtures en `public/` ni `dist/`. Añade pruebas para cambios de comportamiento relevantes, sin duplicar la implementación.
- Ejecuta las comprobaciones pertinentes con pnpm y, antes de cerrar cambios funcionales, la suite, tipos y build disponibles. Las pruebas HTTP requieren puertos locales. No hay script de lint actualmente; no inventes resultados. Informa fallos y límites de la verificación.
- Documentación estándar en raíz: `README.md`, `CHANGELOG.md`, `CONTRIBUTING.md`, `AGENTS.md` y `LICENSE`. Dentro de docs, nombres en minúsculas y kebab-case. Actualiza referencias y comprueba enlaces al renombrar. Mantén las guías centradas en el producto actual; el historial de versiones pertenece a CHANGELOG.
- El repositorio no acepta ni revisa contribuciones externas: consulta `CONTRIBUTING.md`. MIT cubre el framework con el aviso confirmado `Copyright (c) 2026 Gabriel Chávez Riera`; la licencia de contenidos personales es independiente.
